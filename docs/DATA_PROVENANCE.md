# Spelling data provenance

This document records where every piece of data used by the local spelling engine comes from, what this
repository redistributes, and what it deliberately does not. It is a factual record, not legal advice.

## What ships in this repository

| File | Contents | Source | Status |
|---|---|---|---|
| `data/spelling_assets.json`, `frontend/src/data/spelling_assets.json` (identical) | `words`, `logFreq` (60,062 words) | symspellpy 6.10.0 `frequency_dictionary_en_82_765.txt`, top 60,000 entries, plus project vocabulary | Redistributed with attribution; see [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md) |
| | `bigrams` (40,000 pairs) | symspellpy 6.10.0 `frequency_bigramdictionary_en_243_342.txt` | Redistributed under symspellpy's MIT licence; **upstream source of this list is not documented by SymSpell** (open question below) |
| | `letterNext` (26x26 letter-transition table) | Computed from the top 20,000 words above | Derived from the unigram list |
| | `errorModel` (5 edit costs, first-letter multiplier) | Authored for this project: unit-cost Damerau-Levenshtein with a keyboard typing prior | Project-authored; see `PROJECT_ERROR_MODEL` in `scripts/build_spelling_assets.py` |
| | `params` (6 scoring parameters) | Tuned only on the dev split of `data/chat_spelling_eval.json` and a project-authored list of rare words | Project-authored |
| `data/chat_spelling_eval.json` | 110 chat sentences (typo and clean, dev/test splits) | Written by `scripts/author_chat_eval.py`; the file is reproducible byte-for-byte from that script | Project-authored |
| `backend/tests/fixtures/spelling_parity.json` | Browser-engine outputs used to check the Python port | Generated by `scripts/generate_spelling_parity.mjs` from project-authored text only | Project-authored |
| `data/ai_benchmark_results.json` | Results of `scripts/benchmark_ai_providers.py` on its 7 built-in project-authored cases | Project-authored (dated snapshot) | Project-authored |

The engine also contains a hand-curated typo map (`COMMON_TYPOS` in `frontend/src/utils/spellingEngine.js` and
`backend/app/services/spelling_engine.py`, 196 entries, mostly chat abbreviations and well-known misspellings
such as "teh" and "recieve"). Its provenance is not recorded in version history. About half of its entries also
occur in the misspelling lists below, which is expected for very common English misspellings, but it has not been
proven independent of them.

is "Unknown". This is a likely download source, not a confirmed one.

## History of the runtime asset

Earlier versions of `spelling_assets.json` (asset `version` 2) contained an `errorModel` computed from
`data/train_pairs.json` (94% of those pairs came from Birkbeck) and `params` tuned partly on `data/val_pairs.json`.
Asset `version` 3 replaced both with the project-authored values described above. No field of the current asset
is computed from the unresolved corpora. The word list, bigram list and letter table did not change.

Measured effect of that replacement (same engine code, `node scripts/evaluate_spelling.mjs`):

| Metric | v2 (corpus-derived) | v3 (project-authored) |
|---|---|---|
| Chat test split, auto-correct recall / wrong fixes | 0.674 / 0 | 0.837 / 0 |
| Chat test split, with suggestions: precision / recall | 0.902 / 0.860 | 0.951 / 0.907 |
| Clean chat sentences falsely changed | 0 | 0 |
| Local-only Norvig test pairs, auto precision / recall | 0.941 / 0.316 | 0.926 / 0.436 |

The Norvig test pairs were used for this comparison only, never for tuning. The chat test split shares one
sentence with the dev split.

## Rebuilding

Everything needed to rebuild the shipped asset is in the repository:

```bash
backend/.venv/Scripts/python.exe scripts/build_spelling_assets.py   # words, bigrams, letterNext, errorModel
node scripts/evaluate_spelling.mjs --tune                            # params, from the chat dev split only
node scripts/generate_spelling_parity.mjs                            # backend parity fixture
node scripts/evaluate_spelling.mjs                                   # evaluation report
```

Developers who obtain the third-party corpora themselves can place them in `archive/` and `archive (1)/` and run
`scripts/prepare_spelling_dataset.py` to produce the local-only comparison data. The test
`frontend/src/test/spelling.test.jsx` runs its word-pair regression check only when `data/test_pairs.json` exists.
